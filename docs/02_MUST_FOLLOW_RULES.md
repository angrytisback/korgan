# 02. STRICT ENGINEERING & ARCHITECTURAL MANDATES (MUST FOLLOW)

All code generated by human developers or AI Agents MUST comply 100% with the rules below.

## 1. Architectural Pattern: Hexagonal Architecture (Ports & Adapters)

The codebase must be strictly divided into four concentric layers with unidirectional dependency flow (`Adapters -> Application -> Domain`):

1. **`domain` (Pure Rust, Zero I/O):**
   - Contains core entities (`User`, `Session`, `AuditLog`), Value Objects (`EmailAddress`, `RawPassword`, `PasswordHash`, `UserId`), and Domain Errors.
   - Zero dependencies on HTTP (`axum`), Database (`sqlx`), or Redis (`fred`).
   - Use the **Newtype Pattern** with smart constructors (e.g., `EmailAddress::try_from(String)`) so invalid state is unrepresentable in memory.

2. **`ports` (Traits / Interfaces):**
   - **Inbound Ports:** Use-case traits invoked by HTTP handlers or CLI commands.
   - **Outbound Ports:** Repository traits (`UserRepository`, `SessionRepository`), Cache/Token store traits (`TokenStore`, `RateLimiter`), and External Service traits (`MailSender`, `BreachedPasswordChecker`, `PasswordHasher`, `JwtSigner`).
   - All outbound traits must be `Send + Sync + 'static` to support `Arc<dyn Trait>` dependency injection.

3. **`application` (Use Cases & Orchestration):**
   - Implements business workflows (`RegisterUserUseCase`, `AuthenticateUserUseCase`, `RotateRefreshTokenUseCase`, etc.).
   - Coordinates transactions, dispatches background jobs (e.g., sending emails, writing audit logs), and enforces security policies.

4. **`adapters` (Infrastructure & Delivery):**
   - **Inbound:** `axum` routers, extractors, middlewares, OpenAPI (`utoipa`) annotations.
   - **Outbound:** PostgreSQL (`sqlx`) implementations, Redis (`fred`/`deadpool-redis`) implementations, SMTP/Resend/Console mail adapters, HIBP HTTP client.

## 2. Pluggable Configuration & Dual-Mode Token Delivery

- **Runtime Switching:** Every external dependency adapter must be selectable via environment variables (`config.toml` or `.env`):
  - `MAIL_PROVIDER`: `console` | `smtp` | `resend` | `ses`
  - `HIBP_ENABLED`: `true` | `false`
  - `TOKEN_DELIVERY_MODE`: `dual` | `header_only` | `cookie_only`
- **Dual-Mode Auth Extraction:**
  - When `X-Client-Type: web` (or cookie mode is requested), issue Refresh and Access tokens as `HttpOnly; Secure; SameSite=Strict; Path=/` cookies alongside CSRF protection (`Double-Submit Cookie` or custom header check).
  - When `X-Client-Type: mobile` / `cli` (or default), issue tokens in the JSON payload and read Access Tokens from `Authorization: Bearer <token>`.

## 3. Cryptography & Secret Hygiene Rules

- **Memory Zeroization:** All structs holding plaintext passwords, raw TOTP secrets, raw refresh tokens, or private keys MUST derive or implement `zeroize::Zeroize` and `zeroize::ZeroizeOnDrop`.
- **Redacted Debug & Serialization:** Wrap sensitive strings in `secrecy::SecretString` or custom types that output `"[REDACTED]"` in `fmt::Debug` and `fmt::Display` to prevent accidental logging in `tracing`.
- **Constant-Time Comparisons:** Any comparison of hashes, OTP codes, or tokens in application memory MUST use `subtle::ConstantTimeEq`.
- **Timing-Attack Mitigation on Login/Forgot-Password:**
  - Pre-compute a dummy Argon2id hash at startup.
  - When a login request arrives for a non-existent email, verify the provided password against the dummy Argon2id hash so the response latency is indistinguishable from a valid user's failed login.
- **Encrypted MFA at Rest:** TOTP secrets stored in PostgreSQL MUST be encrypted using **AES-256-GCM** (via the `aes-gcm` crate) with a random 96-bit nonce per record, using a master key loaded from environment variables.
- **CPU-Bound Offloading:** Argon2id hashing and verification are CPU-intensive and take 50-250ms. They MUST be executed inside `tokio::task::spawn_blocking` so they never starve the async Tokio worker threads.

## 4. Database & Transaction Discipline

- **Compile-Time SQL Verification:** Use `sqlx` macros (`sqlx::query!`, `sqlx::query_as!`) and maintain an up-to-date `.sqlx` offline metadata directory for CI/Docker builds.
- **Explicit Transactions:** Multi-step state mutations (e.g., resetting a password + appending to `password_history` + revoking all `sessions` + inserting `audit_logs`) MUST execute inside a single ACID PostgreSQL transaction (`sqlx::Transaction`).
- **Opaque Token Storage:** Never store raw Refresh Tokens, Email Verification Tokens, or Password Reset Tokens in PostgreSQL or Redis. Generate 32 bytes of CSPRNG entropy (`rand::rngs::OsRng`), encode as Base64URL for the user, and store ONLY the **SHA-256 hash** in the database/cache.

## 5. Observability, Auditing & OpenAPI Documentation

- **Every Endpoint Annotated:** Every Axum handler, request DTO, and response DTO must include `#[utoipa::path(...)]` and `#[derive(ToSchema)]` with realistic examples and documented RFC 9457 error responses (`400`, `401`, `403`, `409`, `422`, `429`, `500`).
- **Correlation IDs:** Middleware must read `X-Request-Id` (if valid UUID) or generate a new `UUIDv7`, attach it to the `tracing` span, return it in the response header, and include it in RFC 9457 error `instance` fields.
- **Immutable Audit Trail:** Every security-sensitive action (`register`, `login_success`, `login_failed`, `mfa_challenged`, `mfa_enabled`, `mfa_disabled`, `password_changed`, `password_reset`, `email_changed`, `session_revoked`, `token_reuse_detected`) MUST write an immutable record to `audit_logs`.
